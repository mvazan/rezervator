# Nástěnka: nejnovější nahoře, čerstvé oznamy na kiosku, nové v appce — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Nástěnka lists newest first in the app and on the kiosk; the kiosk highlights fresh notices or keeps them longer (admin's choice, 0081); the app highlights the notices that were unread when the board opened, for that visit only.

**Architecture:** `splitNotices` orders by `noticePostedAt` descending (one change for both surfaces). Pure helpers `isFreshNotice` / `kioskNoticeTurn` drive the kiosk card's and status bar's one-shot per-notice turns and the „NOVÉ“ chip; two `schedule_settings` columns hold the admin's choice. The app board reuses the set of notices it marks read on opening as its `isNew` set — no database change for the app.

**Tech Stack:** Flutter 3.38 + Riverpod 3, Supabase (migration + tenancy SQL suite).

Spec: `docs/superpowers/specs/2026-10-15-notices-newest-design.md`. Branch `notices-newest` from `main` f103e28.

```sql
-- 0081 — fresh notices on the kiosk (Správa → Kiosk → Nástěnka). A notice
-- is fresh while it has been up for fewer than kiosk_notices_fresh_days
-- days (1–14, default 3), counted from when it went up: visible_from for a
-- notice posted ahead of time, created_at otherwise. What a fresh notice
-- gets, on the panel's card and in the status bar, is
-- kiosk_notices_fresh_mode:
--
--   off        nothing
--   highlight  the „NOVÉ“ label (the default)
--   longer     twice the turn (kiosk_notices_rotation_seconds) before the
--              next notice
--   both       the label and the longer turn
--
-- The kiosk works it out itself from the settings row and the notices it
-- already reads. public_week needs nothing: it hands out an allow-list of
-- its six settings, so neither column reaches anon.
--
-- Re-runnable on purpose, like 0064 and 0065: the columns come only when
-- missing, and each check only when it is not there yet.

alter table schedule_settings
  add column if not exists kiosk_notices_fresh_mode text not null
    default 'highlight',
  add column if not exists kiosk_notices_fresh_days smallint not null
    default 3;

do $$
begin
  if not exists (select 1 from pg_constraint
                  where conrelid = 'public.schedule_settings'::regclass
                    and conname = 'schedule_settings_kiosk_notices_fresh_mode_check') then
    alter table schedule_settings
      add constraint schedule_settings_kiosk_notices_fresh_mode_check
      check (kiosk_notices_fresh_mode in ('off', 'highlight', 'longer', 'both'));
  end if;
  if not exists (select 1 from pg_constraint
                  where conrelid = 'public.schedule_settings'::regclass
                    and conname = 'schedule_settings_kiosk_notices_fresh_days_check') then
    alter table schedule_settings
      add constraint schedule_settings_kiosk_notices_fresh_days_check
      check (kiosk_notices_fresh_days between 1 and 14);
  end if;
end $$;

comment on column schedule_settings.kiosk_notices_fresh_mode is
  'What a fresh notice gets on the kiosk (0081): off | highlight (the NOVÉ label) | longer (twice kiosk_notices_rotation_seconds) | both. Default highlight.';
comment on column schedule_settings.kiosk_notices_fresh_days is
  'A notice is fresh on the kiosk while it has been up (visible_from, else created_at) for fewer days than this (0081), 1–14, default 3.';
```

  ```dart
  // lib/domain/messages.dart
  DateTime noticePostedAt(Message m) => m.visibleFrom ?? m.createdAt;
  ({List<Message> active, List<Message> expired, List<Message> scheduled})
  splitNotices(Iterable<Message> notices, DateTime now);
  // active, expired: newest first by noticePostedAt, ties by id descending;
  // scheduled: by visibleFrom ascending, then createdAt, then id ascending.
  // noticeFooter's „vyvěšeno“ day is noticePostedAt's local day.

  // lib/domain/models.dart
  enum KioskNoticesFresh {
    off, highlight, longer, both;
    static KioskNoticesFresh parse(String? value); // unknown / null -> highlight
    bool get highlights; // highlight || both
    bool get lingers;    // longer || both
  }
  // ScheduleSettings({..., this.kioskNoticesFresh = KioskNoticesFresh.highlight,
  //                   this.kioskNoticesFreshDays = 3, ...})
  final KioskNoticesFresh kioskNoticesFresh;   // fromJson 'kiosk_notices_fresh_mode'
  final int kioskNoticesFreshDays;             // fromJson 'kiosk_notices_fresh_days', ?? 3

  // lib/domain/kiosk_panel.dart
  List<Message> kioskNotices(Iterable<Message> messages, DateTime now); // unchanged, now newest first
  bool isFreshNotice(Message m, DateTime now, int days);
  Duration kioskNoticeTurn(Message m, {required DateTime now,
      required Duration turn, required KioskNoticesFresh fresh, required int days});
  ```
  `isFreshNotice` = `!noticePostedAt(m).isAfter(now) && now.difference(noticePostedAt(m)) < Duration(days: days)`. `kioskNoticeTurn` = `turn * 2` when `fresh.lingers && isFreshNotice(m, now, days)`, else `turn`. The admin dropdown (Task 4) writes `KioskNoticesFresh.name` as the column value.
