# Rezervátor — cleanup 5: UI dedup rozvrhu (plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One day column renders every calendar board (app week view and kiosk), one `SlotTile` renders every lane cell (a `row` variant replaces the kiosk's private `_laneRow`/`_rowShell`), and `WeekScreen.build` stops being a 460-line function. Adding a slot state or a view mode then touches one file.

**Architecture:** `ScheduleDayColumn` (new, `lib/features/schedule/widgets/schedule_day_column.dart`) is the merged `_DayColumn` of `week_calendar_view.dart` and `kiosk_board_view.dart`: block cards at true time, off-block bands, closed background, the "now" line, and — only when the optional hooks are given — tap-to-add, click-to-edit and hold-to-drag. Each board supplies its lane-row renderer: the week view keeps `slotTileFor` (compact tiles with the digit beside them), the kiosk resolves its own policy into `SlotTile(size: SlotTileSize.row, laneDigit: …)`. Shared constants (`laneRowRefHeight`, `blockCardHeaderHeight`, `brandGradientColors`) replace the copied literals. `WeekScreen` splits into `WeekHeader` (the top strip) and `ScheduleActions` (the booking/cancel/edit/move flows), leaving the screen as state + composition.

**Tech Stack:** Flutter 3.38 / Dart 3.10; no backend change. Widget tests (`kiosk_test` 20, `week_screen_test` 32) are the safety net — they pin card keys (`cal-block-<id>`), `CalendarColumn`, `＋` text on kiosk free rows, `Icons.add` on week free tiles, header geometry.

**Branch:** `cleanup-5-ui` from `main` (after PR #54). Stream B (controller): 5a; Stream W (subagent worktree): 5b; then the controller threads the hook objects (5c).
